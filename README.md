# ♞ CryptoChess — шахматы со ставками в криптовалюте

PWA-приложение для шахматных матчей с ончейн-ставками в BEP-20 токене (BNB Smart Chain).

- **Вход** — только через криптокошелёк (MetaMask / any EIP-1193). Адрес кошелька = профиль игрока, статистика считается из ончейн-контракта.
- **Ставки** — от 50 000 до 1 000 000 токенов, шаг 50 000. Оба игрока lock-ят деньги в эскроу; победитель забирает 95%, **5% комиссии уходит на адрес `0xc2e5650f84Eeb9e4011afbb398108ea302cB17A6`** (комиссия удерживается эскроу, сам токен 0%).
- **Время партии** — 15 минут, 30 минут, 1 час или сутки (фиксированные варианты, проверяются в контракте).
- **Языки** — русский (по умолчанию) и английский.

## Структура

```
contracts/ChessEscrow.sol   — эскроу-контракт (feeBps=500, feeRecipient=0xc2e5...17A6)
server/relay.js             — WebSocket relay (порт 8081) для синхронизации ходов
src/                        — React-приложение (Vite, ethers v6, chess.js, i18next)
```

## 1. Деплой контракта (BNB Smart Chain)

Контракт — обычный ERC-20 эскроу без зависимостей (можно компилировать в Remix/Hardhat/Foundry).

Параметры конструктора:

| Параметр | Значение |
|---|---|
| `_token` | `0x62a3e247e28cad2d2902cd2dc2e6aea7cdd14444` |
| `_feeBps` | `500` (5%) |
| `_feeRecipient` | `0xc2e5650f84Eeb9e4011afbb398108ea302cB17A6` |

```
constructor(IERC20 _token, uint16 _feeBps, address _feeRecipient)
  → new ChessEscrow(0x62a3e247e28cad2d2902cd2dc2e6aea7cdd14444, 500,
                    0xc2e5650f84Eeb9e4011afbb398108ea302cB17A6)
```

После деплоя впишите адрес контракта в `src/lib/config.js`:

```js
export const ESCROW_ADDRESS = "0x...адрес ChessEscrow...";
```

В личном кабинете игрока есть рекламный блок с кнопкой «Купить токен сейчас»,
которая ведёт на страницу покупки в Pons Family Launchpad:
`https://www.ponsfamily.com/launchpad/0xa27D0E80a52fF47886DeFBCBeD679a9A8A23FAe2`
(меняется переменной `TOKEN_BUY_URL` в `src/lib/config.js`). Тексты рекламы — в `src/i18n/*.json`.

### Механика

1. `createGame(stake, duration)` — создатель открывает матч, stake переводится в эскроу.
2. `joinGame(id, stake)` — вызовшийся вносит не меньше ставки создателя, матч активен.
3. В процессе игры проигравший вызывает `resign(id)` (сдача или подтверждение истечения времени) — победитель получает `100% − 5%`, на `feeRecipient` уходит 5% банка.
4. `agreeDraw(id)` — оба игрока согласились → ставка делится пополам (комиссия тоже удерживается).
5. `cancelGame(id)` — создатель отменяет матч до подключения соперника, деньги возвращаются.

## 2. Новый игровой токен CCHESS и обменник GROK/CCHESS

### Настройка окружения

Создайте файл `.env` из шаблона:

```bash
cp .env.example .env
```

Пример заполнения:

```env
VITE_GROK_TOKEN_ADDRESS=0x62a3e247e28cad2d2902cd2dc2e6aea7cdd14444
VITE_CCHESS_TOKEN_ADDRESS=0x...
VITE_CCHESS_EXCHANGE_ADDRESS=0x...
VITE_ESCROW_ADDRESS=0x...
VITE_RELAY_URL=ws://localhost:8081
```

Устаревшие имена `VITE_GAME_TOKEN_ADDRESS` и `VITE_GAME_EXCHANGE_ADDRESS` также поддерживаются как совместимость для старых деплой-скриптов.

Новый игровой токен уже добавлен в проект отдельно от legacy-эскроу `ChessEscrow`:

- `contracts/CryptoChessToken.sol` — ERC-20 `CCHESS`, фиксированная эмиссия `1_000_000_000` токенов, minted в treasury.
- `contracts/CryptoChessExchange.sol` — обменник по курсу `1 GROK = 1 CCHESS` без комиссии в приложении. GROK хранится как резерв для выкупа `CCHESS` назад.
- `scripts/deploy-token-system.cjs` — деплой токена, обменника и отдельного escrow под игровой токен.

Профиль подключён к контрактам CCHESS/GROK в BNB Smart Chain через адреса по умолчанию в `src/lib/config.js`; их можно переопределить переменными `VITE_CCHESS_TOKEN_ADDRESS` и `VITE_CCHESS_EXCHANGE_ADDRESS`. В профиле отображаются балансы, инвентарь и резерв; продажа CCHESS отключается, пока резерв GROK пуст.

Рекомендуемая схема миграции:

1. Сначала оставляем legacy `ChessEscrow` в приложении, чтобы текущие матчи и старые ссылки не ломались.
2. Деплоим новый `CryptoChessToken` + `CryptoChessExchange` и передаём часть CCHESS в обменник как игровую инвентаризацию.
3. Подключаем обменник в профиль и используем его только внутри приложения.
4. После проверки реального поведения и миграции пользователей старый escrow можно отключить или оставить как исторический контракт.

> Важный момент: нельзя удалять существующий `ChessEscrow` слепо, пока у него остаются зависимости в UI и действующие матчи/ссылки. Для безопасного перехода нужен план миграции и последующая проверка на тестовой сети.

## 3. Запуск приложения

### Подключение кошелька на GitHub Pages

Для кнопки подключения кошелька требуется Thirdweb Client ID:

1. Создайте Client ID на [thirdweb.com/create-api-key](https://thirdweb.com/create-api-key).
2. В настройках репозитория откройте **Settings → Secrets and variables → Actions → Variables → New repository variable**.
3. Создайте variable с именем `VITE_THIRDWEB_CLIENT_ID` и вставьте Client ID в значение. Можно также добавить его как Actions secret с таким же именем.
4. Повторно запустите workflow **Deploy to GitHub Pages** через **Actions → Deploy to GitHub Pages → Run workflow**.

Client ID попадёт в браузерную сборку, поэтому при возможности ограничьте его разрешёнными доменами в настройках thirdweb. Не добавляйте его непосредственно в исходники или коммиты.

Для локального запуска задайте `VITE_THIRDWEB_CLIENT_ID` в `.env` (см. `.env.example`).

### Деплой WebSocket relay на Render

Для бесплатных онлайн-матчей, поиска соперника и синхронизации часов нужен постоянно доступный WebSocket relay. Конфигурация Render находится в `render.yaml` и создаёт Node-сервис с health check и постоянным диском для состояния комнат. Постоянный диск требует платного плана Render.

1. Подключите репозиторий к Render и создайте Blueprint из `render.yaml`.
2. Дождитесь статуса **Live** и скопируйте домен сервиса, например `crypto-chess-relay.onrender.com`.
3. В GitHub откройте **Settings → Secrets and variables → Actions → Variables** и задайте `VITE_RELAY_URL` со значением `wss://crypto-chess-relay.onrender.com`.
4. Повторно запустите workflow **Deploy to GitHub Pages**. Он проверяет, что production relay задан по `wss://`, прежде чем публиковать сайт.

Не добавляйте завершающий путь или секреты в `VITE_RELAY_URL`; relay принимает WebSocket-подключения по корневому пути `/`.

```bash
npm install
npm run dev       # фронтенд, http://localhost:5173
npm run server    # relay для синхронизации ходов, ws-порт 8081
npm run build     # production-сборка в dist/
```

Для игры вдвоём relay должен быть доступен обоим игрокам (локально — `ws://localhost:8081`, в продакшене — адрес Render из `VITE_RELAY_URL`).

Бесплатная игра (бот, приглашение и поиск соперника) поддерживает 5, 15 и 30 минут, 1 час и 24 часа. Токеновые матчи используют только сроки, поддерживаемые текущим неизменяемым escrow-контрактом: 15 и 30 минут, 1 час и 24 часа.

В кошельке выберите сеть **BNB Smart Chain (id 56)** и убедитесь, что на балансе есть токен `0x62a3...4444` (продажа токена — через внешний P2P/DEX-партнёра).

## Ограничения (важно знать)

- Роль игрока на доске: создатель — белым, вызвавшийся — чёрным. Создатель создаёт матч, а вызвавшийся подключается через лобби или связью с ID матча.
- Когда время игрока истекает, контракт ждёт, пока проигравший подтвердит результат вызовом `resign()` (приложение подсвечивает эту кнопку). Выигравший не может вывести средства сам в одностороннем порядке — это осознанная защита от недобросовестных действий.
- Для торговых/итоговых интеграций (рейтинги, ордера) можно расширять контракт событиями `Resigned`/`DrawSettled`.
